## 新命令

Scene Planning 得到 GPT JSON 后：

```bash
python3.12 tools/run.py EP002 --apply-director-plan episodes/EP002/director_state/Scene01/Scene_Director_Plan_RESULT.json
```

PASS 后：

```text
Scene01/
├── Scene_Director_Plan_RESULT.json
├── Director_Plan_Validation_Result.json
├── Scene_Plan.json
├── decisions/
│   └── ShotXX-XX_DirectorDecision.json
└── shots/
    └── ShotXX-XX_State.json
```

Runtime 进入：

```text
DIRECTOR_QA_REQUIRED
```

注意：此时 **还不能生产 Shot**。

Phase4 Director QA PASS 后才允许锁定 Scene。

## Validator 当前硬检查

- JSON Schema
- Episode / Scene 对应
- Shot ID / order 连续
- why_this_shot / why_not_previous_shot
- coverage_reason（由 GPT 提供，Python 不从 composition 反推）
- composition_intent
- camera reason / movement reason
- axis_status（由 GPT 明确锁定）
- visible / partial character 必须有显式 Character Master 映射
- Frozen Moment 物理边界
- Camera Gap
- Continuity / Previous Frame Policy
- Scene End
- 相邻 Shot 高度同构的 Micro-action Review Gate

Validator 只拒绝或要求重规划，不替 GPT 修改导演方案。

`scene_assets.character_assets` 由 GPT Director 明确填写；Python 只把可见角色对应的
Character Master 和 Outfit Master 编译进 `required_assets`，不按角色名猜测文件。

当前实现还会检查 Scene Skeleton 的 `next_scene`，以及每个非末镜
`next_shot` 是否连续，防止 Director Plan 与 Runtime 导航分叉。

Camera Gap 补齐并登记新 Camera Master 后，执行 `python3.12 tools/run.py EP002 --build`：
Runtime 会回到当前 Scene 的 `PLAN_CURRENT_SCENE`，由 GPT 重新完成 Camera Match。
