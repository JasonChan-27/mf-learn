# Director State Architecture — V4.1 Delta

本文件只记录 V4 → V4.1 的状态层变更。

## 核心边界

```text
GPT Director
→ Scene_Director_Plan_RESULT.json
→ Python Validator
→ GPT Director QA
→ Python Director State Compiler
→ Scene_Plan / DirectorDecision / Shot_State
→ Runtime / Prompt Compiler / Builder
```

## 新增状态真相

### Scene_Director_Plan.schema.json

GPT Director 的唯一正式 Scene Planning 输出合同。

它包含导演创作字段，例如：

- narrative_purpose
- audience_feeling
- information_gain
- why_this_shot
- why_not_previous_shot
- composition_intent
- camera_reason
- camera_motion_reason
- frozen_moment
- shot_delta

Python 不生成这些字段。

### Director_Decision.schema.json

保存每个 Shot 的导演理由，供 Director QA、Scene QA、评分和问题归因使用。

Builder 与 Prompt Compiler 不应依赖这些“为什么”字段进行创作。

### Scene_Plan.schema.json

由通过 QA 的 Scene Director Plan 编译得到。

这是 Scene 执行结构，不是 GPT 创作入口。

### Shot_State.schema.json

纯执行状态。

所有创作内容必须已经从 GPT Director Plan 写入，不允许 Python 补写 Frozen Moment、Composition、Camera Motion 等导演内容。

### Runtime_State.schema.json

V4.1 新增正式 next_action：

```text
PLAN_CURRENT_SCENE
CAMERA_MATCH_REQUIRED
DIRECTOR_QA_REQUIRED
GENERATE_CURRENT_SHOT_PACKAGE
WAIT_FOR_IMAGE_APPROVAL
NEED_NEW_CAMERA
NEED_ASSET
EPISODE_COMPLETE
```

Phase 5 Runtime 重构完成后，旧 V4 导航值已经从正式 Runtime Schema 删除。
当前只接受 V4.1 状态机定义的 `next_action`。

### Camera_Match_Result.schema.json

Camera Gap 的字段级恢复合同。Build 刷新 Camera Library 后，原 Director Plan 保留；
GPT Director 只为明确的缺口 Shot 返回 `selected_camera`、`camera_status` 与
`camera_reason`。Python 验证当前 Episode 的显式 Camera Selection，回填后运行完整
Plan Validation，并强制重新进入 Director QA。

## Phase7 Builder

正式 Builder 位于：

```text
tools/build_shot_package.py
```

它只消费锁定的 Runtime / Scene State / Shot State 与 Asset Registry，负责：

- 调用 Pure Prompt Compiler；
- 验证并复制当前 Shot 必需资产；
- 执行 Previous Frame Policy；
- 生成版本化 Package、`required_assets.json` 和 `upload/`；
- 成功后把 Shot 更新为 `PROMPTED`。

`production_runtime.py` 不再拼 Prompt 或组装 Package，只负责审批和状态推进。
Builder 不读取 DirectorDecision，不根据导演理由二次创作。

## Phase8 Workflow

V4.1 唯一正式用户入口为：

```text
python3.12 tools/run.py <EPISODE_ID> [ACTION]
```

正式流程由 `00_START_HERE.md`、`00_WORKFLOW.md` 与
`director/Production_Standard.md` 定义。旧 V2/V4 的一次性 Production Prompt
流程不再进入 Build Package。Context Pack 只请求 GPT Director Plan / QA 纯
JSON；Prompt 继续由锁定 Shot State 确定性编译。

## Phase9 Stable Acceptance

Phase9 使用 EP002 与 83 个已登记 Master 文件完成真实资产解析和完整状态机回归：

- `Asset_Selection.md` 的 26 项选择全部唯一解析；
- GPT Director Fixture 显式提供 4 个 Shot、Camera、Coverage、Composition、
  Frozen Moment、Shot Delta 与 Scene End；
- Python 只验证、编译、打包与推进 Runtime，不补写或猜测导演决策；
- Scene01 完成后，Runtime 确定性进入 Scene02 / PLANNING；
- 正式 EP002 未加载测试 Fixture，仍保持 Scene01 / PLANNING / Shot Count 0。

完整验收范围见 `V4.1_Phase9_Stable_Acceptance.md`。
